## Panoramica del Modulo

Il **Data Lake** è il cuore dell'architettura dati moderna: un repository centralizzato che ospita dati strutturati e non strutturati a qualsiasi scala. In questo modulo, imparerai a usare lo standard de facto, **Amazon S3** (o compatibili come MinIO), non come un semplice "hard disk nel cloud", ma come una piattaforma intelligente.
Esploreremo come scegliere il formato giusto (Parquet, Avro, Iceberg), come partizionare i dati per ridurre i costi di scansione e come gestire il ciclo di vita del dato (Tiering).

## Obiettivi di Apprendimento

Al termine di questo modulo sarai in grado di:

- **Progettare** la struttura di folder di un Data Lake (Zone: Bronze/Silver/Gold).
- **Scegliere** il formato di file ottimale (Parquet vs JSON vs CSV) in base al caso d'uso.
- **Implementare** strategie di partizionamento (Hive-style partitioning) per accelerare le query (Partition Pruning).
- **Configurare** policy di Lifecycle Management per spostare i dati freddi su storage più economici (Glacier).
- **Integrare** S3 con motori di query come ClickHouse o Athena.
- **Gestire** la sicurezza e l'accesso ai dati (IAM, Bucket Policies).

## Prerequisiti

- Concetti base di Cloud Computing.
- Familiarità con il terminale (AWS CLI utile ma non indispensabile).

## Competenze Acquisite

**Competenze Architetturali:**
- Design di Data Lake scalabili a petabyte.
- Comprensione del trade-off tra costo di storage e costo di compute.
- Scelta dei formati di compressione (Snappy, Zstd, Gzip).

**Competenze Operative:**
- Utilizzo avanzato della CLI S3.
- Debugging di problemi di performance legati al listing di bucket enormi.

## Tempo Stimato

- **Durata Totale:** Circa 5-6 ore.
- **Tempo Consigliato:** 2 settimane.

## Come Usare Questo Modulo

Il Data Lake sembra semplice ("sono solo file!"), ma il diavolo è nei dettagli. Presta massima attenzione alla lezione sul **Partitioning**: una scelta sbagliata qui (es. troppe partizioni piccole) può uccidere le performance del tuo motore di query mesi dopo.
E ricorda: S3 è economico, ma le API call si pagano. Un cattivo design può costare caro.
