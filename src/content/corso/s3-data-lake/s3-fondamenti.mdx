## Amazon S3: Fondamenti e Architettura

Amazon S3 (Simple Storage Service) e' il servizio di object storage piu' utilizzato al mondo e lo standard de facto per il cloud storage. Comprenderne l'architettura e' essenziale per qualsiasi data engineer che lavori con dati di marketing.

## Architettura S3

L'architettura di S3 si basa su quattro concetti fondamentali: bucket, oggetti, chiavi e prefissi.

```
┌─────────────────────────────────────────────────────────────────┐
│  AWS Account                                                    │
│                                                                 │
│  ┌───────────────────────────────────────────────────────┐      │
│  │  Bucket: acme-marketing-lake                          │      │
│  │  Region: eu-west-1                                    │      │
│  │                                                       │      │
│  │  Prefisso: raw/ga4/2024/01/                           │      │
│  │  ┌─────────────────────────────────────────────┐      │      │
│  │  │  Object                                     │      │      │
│  │  │  Key: raw/ga4/2024/01/15/events.parquet     │      │      │
│  │  │  Size: 245 MB                               │      │      │
│  │  │  Storage Class: S3 Standard                 │      │      │
│  │  │  Version ID: v3xK8jF2...                    │      │      │
│  │  │  Metadata: {source: ga4, rows: 1.5M}        │      │      │
│  │  └─────────────────────────────────────────────┘      │      │
│  │                                                       │      │
│  │  Prefisso: raw/crm/                                   │      │
│  │  ┌─────────────────────────────────────────────┐      │      │
│  │  │  Object                                     │      │      │
│  │  │  Key: raw/crm/contacts_20240115.parquet     │      │      │
│  │  │  Size: 89 MB                                │      │      │
│  │  └─────────────────────────────────────────────┘      │      │
│  └───────────────────────────────────────────────────────┘      │
│                                                                 │
│  ┌───────────────────────────────────────────────────────┐      │
│  │  Bucket: acme-marketing-assets                        │      │
│  │  Region: us-east-1                                    │      │
│  └───────────────────────────────────────────────────────┘      │
└─────────────────────────────────────────────────────────────────┘
```

### Bucket

Il bucket e' il contenitore di primo livello. Regole fondamentali:
- Il nome deve essere **globalmente unico** in tutto AWS (non solo nel tuo account)
- Ogni bucket risiede in una **regione specifica** (eu-west-1, us-east-1, ecc.)
- Non esiste un limite al numero di oggetti in un bucket
- Limite massimo: 100 bucket per account (aumentabile su richiesta)

**Convenzione di naming consigliata:**
```
{azienda}-{ambiente}-{funzione}-{regione}

Esempi:
  acme-prod-marketing-lake-eu
  acme-staging-analytics-eu
  acme-prod-assets-us
```

### Oggetti e Chiavi

Ogni oggetto e' identificato dalla combinazione di bucket + key. La dimensione massima di un singolo oggetto e' **5 TB**. Per file superiori a 100 MB, si usa il **multipart upload** che divide il file in parti e le carica in parallelo.

```bash
# Upload di un file grande con multipart automatico
aws s3 cp large_export.parquet s3://acme-marketing-lake/raw/exports/large_export.parquet \
  --expected-size 5368709120

# Il multipart viene attivato automaticamente per file > 8 MB
# Puoi configurare la soglia:
aws configure set default.s3.multipart_threshold 64MB
aws configure set default.s3.multipart_chunksize 64MB
```

### Prefissi

I prefissi simulano la struttura di directory. S3 non ha cartelle reali, ma i prefissi con "/" vengono visualizzati come cartelle nella console AWS e nei tool CLI.

```bash
# Listare tutti gli oggetti con un prefisso specifico
aws s3 ls s3://acme-marketing-lake/raw/ga4/2024/01/ --recursive

# Output:
# 2024-01-15 08:30:00  245000000 raw/ga4/2024/01/15/events_000.parquet
# 2024-01-15 08:30:02  198000000 raw/ga4/2024/01/15/events_001.parquet
# 2024-01-16 08:30:00  256000000 raw/ga4/2024/01/16/events_000.parquet
```


> **Consiglio:**
> Le performance delle operazioni LIST in S3 scalano per prefisso. Se hai milioni di oggetti sotto un singolo prefisso, le LIST saranno lente. Struttura i prefissi in modo gerarchico (per data, per sorgente) per mantenere le LIST rapide.


## Storage Classes

S3 offre diverse classi di storage, ognuna con un diverso bilanciamento tra costo di archiviazione, costo di accesso e latenza di recupero. La scelta della classe giusta puo' ridurre i costi del 60-90%.

| Storage Class | Costo Storage (GB/mese) | Costo Retrieval | Latenza | Disponibilita' | Caso d'uso |
|--------------|------------------------|----------------|---------|----------------|-----------|
| **S3 Standard** | $0.023 | Nessuno | ms | 99.99% | Dati attivi, query frequenti |
| **S3 Intelligent-Tiering** | $0.023 → $0.0125 | Nessuno | ms | 99.9% | Pattern di accesso imprevedibile |
| **S3 Standard-IA** | $0.0125 | $0.01/GB | ms | 99.9% | Dati acceduti < 1 volta/mese |
| **S3 One Zone-IA** | $0.01 | $0.01/GB | ms | 99.5% | Dati riproducibili, non critici |
| **S3 Glacier Instant** | $0.004 | $0.03/GB | ms | 99.9% | Archivio con accesso istantaneo |
| **S3 Glacier Flexible** | $0.0036 | $0.03/GB | 1-12 ore | 99.99% | Archivio, accesso raro |
| **S3 Glacier Deep Archive** | $0.00099 | $0.02/GB | 12-48 ore | 99.99% | Compliance, archivio a lungo termine |


> **Note:**
> I prezzi indicati sono riferiti alla regione US East (N. Virginia) e servono come riferimento relativo. I costi variano per regione. Verifica sempre il pricing ufficiale AWS per la tua regione.


### Esempio Pratico: Scegliere la Storage Class

Per una piattaforma di marketing analytics con 50 TB di dati:

```
Dati ultimi 3 mesi (10 TB)  → S3 Standard         = $230/mese
Dati 3-12 mesi (20 TB)      → S3 Standard-IA       = $250/mese
Dati 1-3 anni (15 TB)       → S3 Glacier Instant    = $60/mese
Dati > 3 anni (5 TB)        → S3 Glacier Deep       = $5/mese
                                                     ─────────
                                            TOTALE:   $545/mese

vs. tutto in S3 Standard:   50 TB × $0.023 × 1024 = $1,178/mese
                                     RISPARMIO:        54%
```

## Policy di Accesso

S3 offre tre livelli di controllo dell'accesso, che lavorano insieme.

### IAM Policies

Controllano cosa possono fare gli utenti e i servizi AWS. Si allegano a utenti, gruppi o ruoli IAM.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowReadMarketingLake",
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::acme-marketing-lake",
        "arn:aws:s3:::acme-marketing-lake/*"
      ]
    },
    {
      "Sid": "AllowWriteRawOnly",
      "Effect": "Allow",
      "Action": "s3:PutObject",
      "Resource": "arn:aws:s3:::acme-marketing-lake/raw/*"
    }
  ]
}
```

### Bucket Policies

Controllano l'accesso a livello di bucket. Utili per concedere accesso cross-account o pubblico.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowClickHouseServiceAccount",
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::123456789012:role/clickhouse-s3-reader"
      },
      "Action": [
        "s3:GetObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::acme-marketing-lake",
        "arn:aws:s3:::acme-marketing-lake/curated/*"
      ]
    },
    {
      "Sid": "DenyUnencryptedUploads",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:PutObject",
      "Resource": "arn:aws:s3:::acme-marketing-lake/*",
      "Condition": {
        "StringNotEquals": {
          "s3:x-amz-server-side-encryption": "AES256"
        }
      }
    }
  ]
}
```

### Block Public Access

Un livello di sicurezza aggiuntivo che blocca qualsiasi accesso pubblico al bucket, indipendentemente dalle policy.

```bash
# Attiva il blocco totale dell'accesso pubblico (consigliato sempre)
aws s3api put-public-access-block \
  --bucket acme-marketing-lake \
  --public-access-block-configuration \
    BlockPublicAcls=true,\
    IgnorePublicAcls=true,\
    BlockPublicPolicy=true,\
    RestrictPublicBuckets=true
```


> **Attenzione:**
> Per un data lake di marketing, il bucket non dovrebbe **mai** essere pubblico. Attiva sempre il Block Public Access. I dati di marketing contengono informazioni sensibili (comportamenti utente, dati PII, metriche business) che non devono essere esposti.


## Versioning

Il versioning mantiene ogni versione di ogni oggetto. Quando sovrascrivi un file, la versione precedente resta accessibile.

```bash
# Abilita versioning
aws s3api put-bucket-versioning \
  --bucket acme-marketing-lake \
  --versioning-configuration Status=Enabled

# Listare le versioni di un oggetto
aws s3api list-object-versions \
  --bucket acme-marketing-lake \
  --prefix raw/ga4/schema.json

# Recuperare una versione specifica
aws s3api get-object \
  --bucket acme-marketing-lake \
  --key raw/ga4/schema.json \
  --version-id "v3xK8jF2abc123" \
  schema_v2.json
```

**Quando usare il versioning:**
- File di configurazione e schema (recupero da errori)
- Dati della zona curated (audit trail)
- Oggetti critici modificati da pipeline automatiche

**Quando non usare:**
- Dati raw append-only (ogni file ha gia' un nome unico con timestamp)
- Dati temporanei o staging

## Lifecycle Rules

Le lifecycle rules automatizzano il movimento degli oggetti tra storage classes e la loro cancellazione. Sono lo strumento fondamentale per l'ottimizzazione dei costi.

```json
{
  "Rules": [
    {
      "ID": "RawDataLifecycle",
      "Status": "Enabled",
      "Filter": {
        "Prefix": "raw/"
      },
      "Transitions": [
        {
          "Days": 90,
          "StorageClass": "STANDARD_IA"
        },
        {
          "Days": 365,
          "StorageClass": "GLACIER_IR"
        }
      ],
      "Expiration": {
        "Days": 1095
      }
    },
    {
      "ID": "CleanupIncompleteUploads",
      "Status": "Enabled",
      "Filter": {
        "Prefix": ""
      },
      "AbortIncompleteMultipartUpload": {
        "DaysAfterInitiation": 7
      }
    }
  ]
}
```

```bash
# Applicare la lifecycle configuration
aws s3api put-bucket-lifecycle-configuration \
  --bucket acme-marketing-lake \
  --lifecycle-configuration file://lifecycle.json
```


> **Consiglio:**
> Aggiungi sempre una regola per pulire i multipart upload incompleti. Questi upload "fantasma" occupano spazio e generano costi senza che tu ne sia consapevole. 7 giorni e' una soglia ragionevole.


## Comandi CLI Essenziali

Ecco i comandi AWS CLI piu' utili per il lavoro quotidiano con S3:

```bash
# === NAVIGAZIONE E DISCOVERY ===

# Listare bucket
aws s3 ls

# Listare oggetti in un prefisso
aws s3 ls s3://acme-marketing-lake/raw/ga4/ --recursive --human-readable

# Contare oggetti e dimensione totale
aws s3 ls s3://acme-marketing-lake/raw/ --recursive --summarize

# === UPLOAD E DOWNLOAD ===

# Upload singolo file
aws s3 cp events.parquet s3://acme-marketing-lake/raw/events.parquet

# Upload di una directory intera
aws s3 sync ./local_data/ s3://acme-marketing-lake/raw/batch_upload/ \
  --exclude "*.tmp" --exclude ".DS_Store"

# Download con filtro
aws s3 sync s3://acme-marketing-lake/curated/funnel/ ./local_funnel/ \
  --exclude "*" --include "*.parquet"

# === GESTIONE ===

# Copia tra prefissi (server-side, veloce)
aws s3 cp s3://acme-marketing-lake/raw/ga4/2024/ \
          s3://acme-marketing-lake/archive/ga4/2024/ \
  --recursive

# Rimuovere oggetti con un prefisso
aws s3 rm s3://acme-marketing-lake/tmp/ --recursive

# === INFORMAZIONI ===

# Dimensione di un prefisso
aws s3api list-objects-v2 \
  --bucket acme-marketing-lake \
  --prefix raw/ga4/2024/01/ \
  --query "sum(Contents[].Size)" \
  --output text

# Metadati di un oggetto
aws s3api head-object \
  --bucket acme-marketing-lake \
  --key raw/ga4/2024/01/15/events.parquet
```

## Alternative S3-Compatible

Il protocollo S3 e' diventato uno standard de facto. Diversi provider offrono storage compatibile con le API S3, permettendoti di usare gli stessi tool e SDK.

| Soluzione | Tipo | Costo Storage | Egress | Caso d'uso |
|-----------|------|--------------|--------|-----------|
| **Amazon S3** | Cloud | $0.023/GB/mese | $0.09/GB | Ecosistema AWS completo |
| **MinIO** | Self-hosted | Costo infrastruttura | N/A | On-premise, dev/test, privacy |
| **Cloudflare R2** | Cloud | $0.015/GB/mese | Gratuito | Risparmio su egress, edge |
| **DigitalOcean Spaces** | Cloud | $0.02/GB/mese | $0.01/GB | Semplicita', costi prevedibili |
| **Backblaze B2** | Cloud | $0.006/GB/mese | $0.01/GB | Archivio, costo minimo |
| **Google Cloud Storage** | Cloud | $0.020/GB/mese | $0.12/GB | Ecosistema GCP |

### MinIO: S3 in Locale

MinIO e' particolarmente utile per lo sviluppo locale e per ambienti on-premise dove i dati non possono lasciare il data center.

```bash
# Avviare MinIO con Docker
docker run -d \
  --name minio \
  -p 9000:9000 \
  -p 9001:9001 \
  -v minio-data:/data \
  -e MINIO_ROOT_USER=minioadmin \
  -e MINIO_ROOT_PASSWORD=minioadmin \
  minio/minio server /data --console-address ":9001"

# Configurare AWS CLI per puntare a MinIO locale
aws configure set default.s3.endpoint_url http://localhost:9000
# Oppure per singolo comando:
aws --endpoint-url http://localhost:9000 s3 ls
```

### Cloudflare R2: Zero Egress

R2 e' particolarmente interessante per i data lake dove i dati vengono letti frequentemente da tool distribuiti, perche' non addebita costi di egress (il trasferimento dati in uscita).

```bash
# Configurare un profilo per R2
aws configure --profile r2
# Endpoint: https://<account-id>.r2.cloudflarestorage.com

# Usare R2 con il profilo
aws --profile r2 s3 ls s3://marketing-lake/
```


> **Note:**
> Quando scegli un provider, considera non solo il costo di storage ma anche l'**egress** (trasferimento dati in uscita). Su AWS S3, il costo di egress ($0.09/GB) puo' superare il costo di storage per dati letti frequentemente. R2 e Backblaze B2 eliminano o riducono drasticamente questo costo.


## Best Practice per il Marketing Data Lake su S3

1. **Abilita il versioning** solo sui prefissi che contengono dati critici o modificabili (schema, configurazioni, zona curated).

2. **Configura lifecycle rules** fin dal primo giorno. I dati grezzi vecchi di 90+ giorni raramente vengono acceduti e possono migrare a Standard-IA.

3. **Blocca l'accesso pubblico** su tutti i bucket del data lake. Usa IAM roles per concedere accesso ai servizi.

4. **Abilita l'encryption at rest** (SSE-S3 o SSE-KMS) come default del bucket.

5. **Configura S3 Access Logging** o CloudTrail per tracciare chi accede a quali dati (essenziale per GDPR compliance).

6. **Usa prefissi strutturati** che facilitino il partizionamento: `{zone}/{source}/{year}/{month}/{day}/`.

7. **Pulisci i multipart upload incompleti** con una lifecycle rule dedicata.
