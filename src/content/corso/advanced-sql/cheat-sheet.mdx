Questa scheda serve come riferimento operativo veloce. Non sostituisce le lezioni: ti aiuta a ricordare **quale funzione usare, con quale struttura, e per quale domanda di business**.

## Formula mentale minima

Ogni window function ha tre decisioni:

1. **gruppo logico**: `PARTITION BY`
2. **sequenza logica**: `ORDER BY`
3. **perimetro della finestra**: `ROWS` o `RANGE`

Schema base:

```sql
funzione() OVER (
    PARTITION BY ...
    ORDER BY ...
    ROWS BETWEEN ...
)
```

## Quale pattern usare

### 1. Voglio mantenere il dettaglio ma aggiungere il totale del gruppo

```sql
sum(amount) OVER (PARTITION BY channel)
```

Usalo per:

- quota sul totale
- benchmark per segmento
- confronto riga vs gruppo

### 2. Voglio una classifica per gruppo

```sql
row_number() OVER (
    PARTITION BY category
    ORDER BY revenue DESC
)
```

Usalo per:

- top N per categoria
- bottom N per paese
- deduplica del record piu' recente

### 3. Voglio confrontare la riga con quella precedente o successiva

```sql
lag(metric) OVER (
    PARTITION BY entity
    ORDER BY month
)

lead(metric) OVER (
    PARTITION BY entity
    ORDER BY month
)
```

Usalo per:

- MoM e WoW
- gap tra eventi
- upgrade e downgrade

### 4. Voglio una cumulata o una media mobile

```sql
sum(metric) OVER (
    ORDER BY day
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
)

avg(metric) OVER (
    ORDER BY day
    ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
)
```

Usalo per:

- running total
- payback day
- smoothing di serie temporali

### 5. Voglio il primo o l'ultimo valore della partizione

```sql
first_value(metric) OVER (
    PARTITION BY entity
    ORDER BY ts
    ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
)

last_value(metric) OVER (
    PARTITION BY entity
    ORDER BY ts
    ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
)
```

Usalo per:

- primo e ultimo ordine
- primo e ultimo prezzo osservato
- stato iniziale e finale di una subscription

### 6. Voglio dividere la distribuzione in bucket

```sql
ntile(4) OVER (ORDER BY total_margin DESC)
```

Usalo per:

- quartili clienti
- decili prodotto
- segmentazione per valore

## Frammenti pronti da riusare

### Quota della riga sul totale del gruppo

```sql
amount / sum(amount) OVER (PARTITION BY channel)
```

### Delta rispetto alla riga precedente

```sql
metric - lag(metric) OVER (
    PARTITION BY entity
    ORDER BY period
)
```

### Variazione percentuale

```sql
(metric - lag(metric) OVER (
    PARTITION BY entity
    ORDER BY period
))
/ nullif(
    lag(metric) OVER (
        PARTITION BY entity
        ORDER BY period
    ),
    0
)
```

### Deduplica del record piu' recente

```sql
WITH ranked AS (
    SELECT
        *,
        row_number() OVER (
            PARTITION BY business_key
            ORDER BY updated_at DESC, id DESC
        ) AS rn
    FROM source_table
)
SELECT *
FROM ranked
WHERE rn = 1;
```

### Primo giorno che supera una soglia cumulata

```sql
WITH running AS (
    SELECT
        month,
        day,
        sum(revenue) OVER (
            PARTITION BY month
            ORDER BY day
            ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
        ) AS cumulative_revenue
    FROM daily_revenue
),
crossed AS (
    SELECT
        month,
        day,
        row_number() OVER (
            PARTITION BY month
            ORDER BY day
        ) AS rn
    FROM running
    WHERE cumulative_revenue >= 100000
)
SELECT month, day
FROM crossed
WHERE rn = 1;
```

## Come scegliere tra le funzioni di ranking

| Funzione | Pareggi | Quando usarla |
|---|---|---|
| `ROW_NUMBER()` | no | top N esatto, deduplica |
| `RANK()` | si, con buchi | classifica competitiva |
| `DENSE_RANK()` | si, senza buchi | tier e livelli |

## `ROWS` vs `RANGE`

| Frame | Logica | Quando e' piu' sicuro |
|---|---|---|
| `ROWS` | conta righe fisiche | cumulative e moving average |
| `RANGE` | include righe con stesso valore di ordinamento | casi con valori equivalenti intenzionali |

<Aside type="caution" title="Errore classico">
Con `LAST_VALUE()` il frame implicito porta spesso a risultati quasi giusti ma semanticamente sbagliati. Specifica sempre il frame completo quando vuoi leggere tutta la partizione.
</Aside>

## Anti-pattern da evitare

### `LIMIT` al posto del ranking per gruppo

`LIMIT 10` non equivale a "top 10 per categoria".

### Window function su dati raw quando la domanda e' mensile

Se devi leggere il mese, aggrega prima per mese.

### `ORDER BY` finale confuso con `ORDER BY` della finestra

Il primo ordina l'output, il secondo definisce il calcolo.

### Deduplica senza tie-breaker

Se due righe hanno lo stesso timestamp, il risultato puo' non essere deterministico.

## Checklist rapida prima di usare una window function

- La granularita' della tabella in input e' quella giusta?
- La partizione risponde davvero alla domanda business?
- L'ordinamento e' stabile anche in caso di pareggio?
- Il frame e' esplicito dove conta?
- Ho protetto i divisori con `nullif(..., 0)`?

## Riepilogo

Le window functions non sono una collezione di trucchi. Sono un modo sistematico per aggiungere contesto alla riga. Se sai riconoscere bene gruppo, sequenza e frame, scegli la funzione corretta molto piu' velocemente e riduci parecchio il rischio di query "plausibili ma sbagliate".
