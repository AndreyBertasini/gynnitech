Se Python è il coltellino svizzero, **SQL (Structured Query Language)** è la forza bruta. È il linguaggio universale dei database e, nonostante abbia più di 50 anni, non è mai stato così attuale. Nel MarTech, SQL è lo strumento con cui estraiamo la verità dai dati grezzi accumulati in BigQuery, Snowflake o ClickHouse.

In questa lezione imparerai i pattern avanzati di SQL per l'analisi dei dati e, soprattutto, come scrivere query che siano veloci ed economiche.

## Il Paradigma Dichiarativo

A differenza di Python (imperativo: "fai questo, poi quello"), SQL è **dichiarativo**. Tu dici al database *cosa* vuoi ottenere ("Voglio la somma delle vendite per paese"), e il database decide il modo più efficiente per andare a prendere i dati sul disco. 

Per essere bravi in SQL bisogna pensare in termini di **Insiemi (Sets)**, non di singole righe.

## Le Window Functions: Il Superpotere dell'Analista

Le Window Functions (funzioni finestra) permettono di fare calcoli complessi tra righe diverse senza dover fare costose auto-join. Sono essenziali per calcolare trend, classifiche e medie mobili.

*Esempio: Calcolare la differenza di vendita rispetto al giorno precedente.*

```
sql
SELECT 
    data,
    revenue,
    revenue - LAG(revenue) OVER (ORDER BY data) as diff_ieri
FROM vendite_giornaliere

```

## CTE (Common Table Expressions) vs Subqueries

Smetti di usare le subqueries nidificate (quelle dentro le parentesi tonde nel `FROM`). Rendono il codice illeggibile. Usa le **CTE** (clausola `WITH`).

```
sql
WITH vendite_pulite AS (
    SELECT user_id, sum(amount) as totale
    FROM ordini
    WHERE status = 'completed'
    GROUP BY 1
)
SELECT * 
FROM vendite_pulite 
WHERE totale > 100

```

Le CTE rendono l'SQL modulare, simile a una ricetta di cucina: prepari gli ingredienti uno alla volta e poi li unisci alla fine.

## Ottimizzazione: Perché la tua query è lenta?

In un Data Warehouse moderno (colonnare), il costo e il tempo dipendono da quanti dati il database deve leggere dal disco.

<Steps>

1. **Seleziona solo le colonne che servono:** `SELECT *` è il male assoluto. Se la tabella ha 100 colonne e te ne servono 2, `SELECT *` ti costerà 50 volte di più.
2. **Filtra presto (Early Filtering):** Metti le clausole `WHERE` il più in alto possibile nelle tue CTE per ridurre il numero di righe elaborate nei passaggi successivi.
3. **Usa il Partizionamento:** Se la tabella è partizionata per data, usa sempre un filtro sulla data. Questo evita che il database legga anni di dati inutili.

</Steps>

<Aside type="danger" title="Attenzione ai JOIN">
  Un `JOIN` tra due tabelle da un miliardo di righe può "uccidere" il database o costare centinaia di euro. Se possibile, cerca di denormalizzare i dati in fase di modeling (vedi lezione *Modeling*) per avere tabelle ampie ("Wide Tables") che non richiedono JOIN frequenti.
</Aside>

## SQL per l'Attribuzione e le Coorti

SQL è perfetto per costruire modelli di attribuzione custom. Puoi usare le Window Functions per identificare qual è stato il primo touchpoint (`FIRST_VALUE`) e l'ultimo (`LAST_VALUE`) per ogni sessione utente, unendo poi i dati con i costi delle campagne.

Anche l'analisi delle coorti si riduce a un paio di `GROUP BY`:
1. Calcoli la data di "nascita" dell'utente (primo acquisto).
2. Calcoli la differenza in mesi tra ogni acquisto successivo e la data di nascita.
3. Raggruppi per mese di nascita e differenza mesi.

## I Dialetti SQL: Non sono tutti uguali

Sebbene lo standard sia lo stesso, ogni database ha le sue particolarità:
- **BigQuery:** Eccellente gestione di dati nidificati (JSON/Struct).
- **ClickHouse:** Funzioni specifiche per la velocità (es. `uniqCombined` per contare gli unici in modo approssimato ma istantaneo).
- **Postgres:** Robustezza e supporto totale per ogni tipo di dato.

<Aside type="tip" title="Usa i commenti">
  Il codice SQL viene scritto una volta ma letto dieci volte. Usa i commenti (`-- commento`) per spiegare *perché* stai filtrando un certo dato o *cosa* rappresenta quella metrica complessa. Il te stesso del futuro ti ringrazierà.
</Aside>

## Conclusione

SQL è lo strumento più potente che un analista possa avere. Padroneggiare le Window Functions e saper ottimizzare le query non ti rende solo più veloce, ma ti permette di estrarre insight che altri non vedono. In un mondo di dati massivi, chi parla SQL è il vero padrone delle informazioni.
