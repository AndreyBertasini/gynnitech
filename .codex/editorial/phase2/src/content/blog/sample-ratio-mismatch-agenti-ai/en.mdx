You designed an experiment with a 50/50 split: half the users see an AI agent, the other half follow the traditional flow. At the end, the groups show a 61/39 split. The dashboard still declares a winner, but stop right there.

This imbalance is called sample ratio mismatch (SRM) and means the observed distribution does not match the expected one. When this happens, the test may be compromised.

## Why it matters

In a properly conducted experiment, groups must be comparable. If you planned a 50/50 split, you expect only small, random differences. A significant imbalance suggests something affected assignment or measurement.

With SRM, you can't tell if the result is due to the variant or because the groups differ.

In AI agents, the risk is higher because triggering can be complex: some users see the agent only if they reach a specific page, have certain permissions, use a particular language, or complete a prior step.

## Common causes in AI agents

SRM can arise from:

- exposure events recorded only when users click the agent;
- bugs preventing a variant from loading on mobile;
- premium segments excluded from a group;
- misconfigured feature flags;
- AI service timeouts for some users;
- analysis filters applied after assignment.

Many of these issues are not visible at a glance. The UI may look normal while the test is already broken.

## How to prevent it

Before launching an experiment:

1. define the exact assignment point;
2. define the exact exposure point;
3. verify both groups record the same events;
4. monitor daily proportions;
5. set alerts if imbalance exceeds a threshold.

Don't wait until the end of the test. Discovering SRM too late wastes time and traffic.

## What to do if it happens

Don't try to salvage the result at all costs. Diagnose first.

Check browser, device, country, plan, app version, load times, API errors, and flag rules. If you find the cause and it affects a limited period, you can clean the data and restart. Often, though, the honest choice is to rerun the test.

Experimental discipline requires humility: a seemingly valid result from a broken test is not an insight but a risk disguised as certainty.

## Applying this without complicating work

To make Sample Ratio Mismatch practical for AI agents, don't start with the newest tool. Start where the team wastes time, debates without data, or makes decisions with incomplete information. That's where you see if the topic has operational value or is just a nice slide idea.

The rule is simple: an agent should not be treated like a brilliant chat. It needs clear inputs, limited tools, controlled memory, and an explicit rule to hand decisions to a human when risk rises.

A useful sequence is:

1. define what data the agent can read and what it must not touch;
2. write the expected result in a verifiable form, not as a vague intention;
3. decide when human review is needed before sending or saving output;
4. measure time saved, errors avoided, and cases where the agent stops.

## What to measure to know if it works

The right question is not "Did we use AI?" or "Did we add a new dashboard?" The right question is: **which decision became faster, clearer, or safer?** If no decision changes, the project risks being mere technical decoration.

Measure at least three levels: operational time saved, result quality, and team confidence in the process. Time alone can mislead: a faster flow that's less controllable isn't an improvement. Quality alone can mislead: a perfect system that's too slow won't truly enter daily work.
