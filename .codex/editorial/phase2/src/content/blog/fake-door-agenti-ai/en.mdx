You have a strong idea: an AI agent that analyzes reports and suggests actions. The tech team estimates four weeks of work. Marketing wants to announce it. Product believes it will be useful.

But do users actually want it?

A fake door helps answer this before building. It shows a realistic entry point, measures interest, then explains the feature is coming or under exploration. Done right, it's a learning tool; done wrong, it's a trap.

## The fake door must not deceive

The ethical boundary is clear: you can test interest but must not waste time or trust.

A good fake door for an AI agent might be a button: "Generate automatic analysis." When clicked, it shows a clear message: "We're evaluating this feature. Would you like to be notified or join the beta?" Don't promise results that don't exist. Don't simulate critical actions. Don't make users think the system is working if it isn't.

## What to measure

Clicks alone aren't enough. Measure:

- how many see the entry point;
- how many click;
- which segments they come from;
- what problem they declare;
- how many request beta access;
- how many accept a short interview.

Qualitative feedback is key to building the right agent, not just the one you imagined.

## When it works best

Fake doors are useful when development cost is high and demand uncertainty is real. Examples:

- agent that prepares campaigns;
- agent that explains dashboards;
- agent that creates automatic segments;
- agent that analyzes customer feedback;
- agent that suggests pricing.

If risk is low and you can prototype in a day, better to build a manual or semi-automatic version and observe.

## From door to product

After testing, don't just look at click rates. Ask: is the problem painful enough? Would users trust the agent? What data is needed? What actions require approval?

A well-designed fake door tells you not only whether to build, but how to start.

## How to apply it without complicating work

Don't start with the newest tool. Start where the team wastes time, debates without data, or makes decisions with incomplete info. An agent isn't a clever chat: it needs clear inputs, limited tools, controlled memory, and explicit rules to hand off decisions to humans when risk rises.

A useful sequence:

1. define which data the agent can access and which it cannot;
2. write expected results in verifiable terms;
3. decide when human review is needed before sending or saving output;
4. measure time saved, errors avoided, and cases where the agent stops.

## What to measure to know if it works

The right question isn't "Did we use AI?" or "Did we add a dashboard?" It's: which decision became faster, clearer, or safer? If no decision changes, the project risks being mere technical decoration.

Measure at least three levels: operational time saved, result quality, and team trust. Time alone can mislead: a faster but less controllable flow isn't an improvement. Quality alone can mislead: a perfect but slow system won't enter daily work.

## Conclusion

Fake doors are a discipline for making decisions under uncertainty: listen without manipulating, respect user signals, and turn interest into a concrete development path. Before building an AI agent, use a fake door to understand if and how to do it right.
