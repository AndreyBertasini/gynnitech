# Marketing Attribution Models

Marketing attribution is not a magic formula but a discipline that helps allocate credit transparently and thoughtfully among the various channels contributing to a conversion. Last click rewards only the channel that closes the sale, first click recognizes who introduced the product, while brand teams often remain invisible because they generate demand before tracking begins. The goal is not to find the perfect model but to understand what you are rewarding and which decisions you can make based on that information.

## Real-world problem

In marketing analytics, the concrete challenge is turning data about budgets, channels, creatives, and audiences into measurable decisions, avoiding confusion between volume, attribution, and incrementality. The key question is: which decision improves thanks to this attribution model? Without a clear answer, the analysis remains decorative rather than competent.

## Conceptual model

The mental process for using an effective attribution model follows these steps:

1. Business question: which decision needs to change?
2. Measurable hypothesis: which signal represents the phenomenon?
3. Reliable data: are the data valid and complete enough?
4. Incremental analysis: does the signal reduce decision uncertainty?
5. Budget decision: what concrete actions will we take?

```mermaid

    A[Business question]

    D --> E
```

| Step | Guiding question | Expected output |
|---|---|---|
| Framing | Which decision must change? | Concrete choice |
| Measurement | Which signal represents the phenomenon? | Metric and granularity |
| Comparison | Against which baseline do I interpret results? | Benchmark or control group |
| Action | What do I do if the signal crosses the threshold? | Decision and follow-up |

## Rigorous formalization

An attribution model is defined as a relationship among four elements:

| Element | Operational definition |
|---|---|
| Unit of analysis | campaign, cohort, touchpoint, or customer segment |
| Signal | incremental margin, CAC payback, adjusted conversion rate, lift, or generated retention |
| Baseline | previous period, holdout group, comparable market, or historical benchmark |
| Decision | reallocate resources, change messaging, stop a tactic, or scale an experiment |

The practical rule is that a metric is useful only if it reduces uncertainty about a specific decision. Otherwise, it is just documentation or risk.

## Classic attribution models

| Model | How it assigns credit | Strengths | Weaknesses |
|-------|-----------------------|-----------|------------|
| Last-click | 100% to last touchpoint | Simple, verifiable | Ignores awareness path |
| First-click | 100% to first touchpoint | Recognizes discovery | Ignores nurturing and final conversion |
| Linear | Evenly across all touchpoints | Fair, simple | Does not distinguish influential touchpoints |
| Time Decay | More weight to recent touchpoints | Realistic for impulse buys | Arbitrary decay rate |
| Position-based (U-shaped) | 40% first, 40% last, 20% others | Balances discovery and conversion | Arbitrary split |

## Data-driven attribution and Shapley values

Modern approaches use Shapley values from cooperative game theory. They calculate each channel's marginal contribution across all possible combinations, assigning credit proportional to how much it increases conversion probability.

```sql
-- Conversion rate by channel combination
SELECT STRING_AGG(channel, '+' ORDER BY channel) AS channel_combo,
       COUNT(*) AS users,
       SUM(converted) AS conversions,
       ROUND(SUM(converted)*100.0/COUNT(*),1) AS conversion_rate
FROM user_journeys GROUP BY user_id;
```

### Real case: Booking.com

Switching from last-click to Shapley values, Booking.com redistributed 18% of budget among channels and increased ROAS by 7%. Top-of-funnel channels like display and video, previously overlooked, proved essential to generating demand.

## Operational insight: attribution models as part of a system

An attribution model never lives in isolation. It is part of a system involving decisions, data, technical constraints, and organizational incentives. The risk is learning formulas without understanding the problem they solve. The first question must be: which decision will this analysis change?

A good approach is:

1. Define the problem in business terms
2. Identify the correct unit of analysis
3. Verify data quality and relevance
4. Build an interpretable metric
5. Segment to avoid misleading averages
6. Turn results into verifiable recommendations

## SQL example: building a control view

This query creates an analytic base with metrics, segments, and time windows to compare periods and groups without rewriting logic.

```sql
WITH base_events AS (
  SELECT
    user_id,
    account_id,
    event_type,
    event_time,
    DATE_TRUNC('week', event_time) AS week,
    source,
    device_type
  FROM events
  WHERE event_time >= CURRENT_DATE - INTERVAL '180 days'
    AND user_id IS NOT NULL
),
weekly_user_metrics AS (
  SELECT
    week,
    user_id,
    COALESCE(source, 'unknown') AS source,
    COALESCE(device_type, 'unknown') AS device_type,
    COUNT(*) AS total_events,
    COUNT(DISTINCT DATE(event_time)) AS active_days,
    COUNT(DISTINCT event_type) AS event_diversity,
    MAX(CASE WHEN event_type IN ('purchase', 'subscribe', 'activation') THEN 1 ELSE 0 END) AS reached_key_outcome
  FROM base_events
  GROUP BY week, user_id, source, device_type
)
SELECT
  week,
  source,
  device_type,
  COUNT(DISTINCT user_id) AS users,
  ROUND(AVG(active_days), 2) AS avg_active_days,
  ROUND(AVG(event_diversity), 2) AS avg_event_diversity,
  ROUND(AVG(reached_key_outcome) * 100, 2) AS key_outcome_rate
FROM weekly_user_metrics
GROUP BY week, source, device_type
ORDER BY week, source, device_type;
```

This foundation allows observing trends, segments, and time variations to formulate sharper hypotheses.

## Python example: checking stability and anomalies

A useful metric must be stable yet sensitive. This script detects anomalous week-over-week variations.

```python
import pandas as pd

# df contains: week, segment, users, key_outcome_rate (percentage)

df = df.sort_values(['segment', 'week']).copy()
df['previous_rate'] = df.groupby('segment')['key_outcome_rate'].shift(1)
df['wow_change_pp'] = df['key_outcome_rate'] - df['previous_rate']
df['rolling_mean'] = df.groupby('segment')['key_outcome_rate'].transform(
    lambda s: s.rolling(4, min_periods=2).mean()
)
df['rolling_std'] = df.groupby('segment')['key_outcome_rate'].transform(
    lambda s: s.rolling(4, min_periods=2).std()
)
df['z_score'] = (df['key_outcome_rate'] - df['rolling_mean']) / df['rolling_std']

anomalies = df[df['z_score'].abs() >= 2].sort_values('z_score')
print(anomalies[['week', 'segment', 'key_outcome_rate', 'wow_change_pp', 'z_score']])
```

This helps avoid reacting to random fluctuations and focus on meaningful changes.

## Real case: Netflix and metric discipline

Netflix builds product decisions around observable behavioral signals like episode completion or search time. It measures not just immediate clicks but quality and implicit satisfaction. This approach prevents optimizing vanity metrics that look good short-term but damage long-term value. The same principle applies here: attribution models must link to outcomes or the analysis is incomplete.

## Common mistakes to avoid

1. Aggregating data too early, hiding opposing patterns
2. Not checking data quality (duplicates, incomplete tracking, inconsistent timezones)
3. Confusing correlation with causation

To reduce risks, every analysis should have explicit metric definitions, segment comparisons, and verification against baselines or control groups.
