# Performance marketing analytics

Performance marketing is often seen as measurable and scalable, but the reality is more nuanced. A campaign might look efficient when considering average CPA alone, but increasing frequency, auction competition, and low-margin orders can degrade results. The real challenge is distinguishing when a channel drives healthy growth versus merely buying more expensive conversions.

## Real problem

Decision-makers face a concrete challenge: differentiating volume of conversions, customer quality, margin, and incrementality. Platform metrics are just a starting point; analysis must connect CPA, margin, and conversion quality to inform decisions effectively.

## Conceptual model

The decision process begins with a business question, translated into a measurable hypothesis. This hypothesis requires reliable data to perform incremental analysis and reach a well-informed budget decision.

```mermaid
flowchart LR
    A[Business question]
    B[Measurable hypothesis]
    C[Reliable data]
    D[Incremental analysis]
    E[Budget decision]
    A --> B
    B --> C
    C --> D
    D --> E
```

| Step | Guiding question | Expected output |
|---|---|---|
| Framing | Which decision needs to change? | A concrete choice, not mere curiosity |
| Measurement | Which signal represents the phenomenon? | Metric, source, and granularity |
| Comparison | Against which baseline do I interpret results? | Benchmark or plausible counterfactual |
| Action | What do I do if the signal crosses threshold? | Decision, owner, and next check |

## Rigorous formalization

Performance marketing analytics involves four elements:

- **Unit of analysis**: campaign, cohort, touchpoint, or customer segment
- **Signal**: incremental margin, CAC payback, adjusted conversion rate, lift, or generated retention
- **Baseline**: prior period, holdout group, comparable market, or historical benchmark
- **Decision**: reallocate resources, change messaging, stop a tactic, or scale an experiment

The practical rule is that a metric is useful only if it reduces uncertainty about a specific decision. Without this link, analysis risks being mere documentation or a source of errors.

## Core metrics

| Metric | Formula | Purpose |
|---------|---------|---------|
| CPA (Cost Per Acquisition) | Spend ÷ Conversions | Pure efficiency measure |
| ROAS (Return on Ad Spend) | Revenue from ads ÷ Ad spend | Return on investment indicator |
| CTR (Click-Through Rate) | Clicks ÷ Impressions | Ad relevance evaluation |
| CVR (Conversion Rate) | Conversions ÷ Clicks | Landing page effectiveness |
| CPC (Cost Per Click) | Spend ÷ Clicks | Cost of traffic |
| Impression Share | Impressions received ÷ Available impressions | Visibility share |

## The average CPA trap

Average CPA can mask significant variation across segments. Segmenting by campaign, keyword, device, region, and time is essential. For example, a $50 average CPA might hide $30 on mobile and $120 on desktop. Cutting desktop and investing in mobile can double efficiency without increasing budget.

## Optimization: not just cutting costs

Removing keywords with high CPA without considering customer value is a mistake. Optimization requires CPA targets differentiated by estimated LTV:

- Segment A (high LTV): CPA target up to $500
- Segment B (medium LTV): CPA target up to $200
- Segment C (low LTV): CPA target up to $50

## Operational insight: viewing performance marketing analytics as a system

Analysis is not an isolated exercise but part of a broader decision system involving data, technical constraints, incentives, and execution quality. A common mistake is calculating metrics without linking them to real decisions. A solid approach follows these steps:

1. Define the problem in business terms
2. Identify the correct unit of analysis
3. Verify data quality and relevance
4. Build an interpretable metric
5. Segment to avoid misleading averages
6. Turn results into verifiable recommendations

## Real case: Netflix and metric discipline

Netflix goes beyond clicks and views. It evaluates quality signals like episode completion, search time, early abandonment, and user return. This approach prevents optimizing vanity metrics that may harm long-term value. Similarly, performance marketing must connect metrics to concrete outcomes and operational decisions.

## SQL example: building a control view

To analyze performance marketing systematically, create a view aggregating events by week, segment, and device, calculating key metrics like conversion rate and user activity. Here's a generic example:

```sql
WITH base_events AS (
  SELECT
    user_id,
    account_id,
    event_type,
    event_time,
    DATE_TRUNC('week', event_time) AS week,
    source,
    device_type
  FROM events
  WHERE event_time >= CURRENT_DATE - INTERVAL '180 days'
    AND user_id IS NOT NULL
),
weekly_user_metrics AS (
  SELECT
    week,
    user_id,
    COALESCE(source, 'unknown') AS source,
    COALESCE(device_type, 'unknown') AS device_type,
    COUNT(*) AS total_events,
    COUNT(DISTINCT DATE(event_time)) AS active_days,
    COUNT(DISTINCT event_type) AS event_diversity,
    MAX(CASE WHEN event_type IN ('purchase', 'subscribe', 'activation') THEN 1 ELSE 0 END) AS reached_key_outcome
  FROM base_events
  GROUP BY week, user_id, source, device_type
)
SELECT
  week,
  source,
  device_type,
  COUNT(DISTINCT user_id) AS users,
  ROUND(AVG(active_days), 2) AS avg_active_days,
  ROUND(AVG(event_diversity), 2) AS avg_event_diversity,
  ROUND(AVG(reached_key_outcome) * 100, 2) AS key_outcome_rate
FROM weekly_user_metrics
GROUP BY week, source, device_type
ORDER BY week, source, device_type;
```

This foundation allows observing trends, segments, and channel differences to form sharper hypotheses.

## Python example: checking stability and anomalies

A useful metric must be stable yet sensitive. To avoid reacting to random fluctuations, identify statistical anomalies week over week:

```python
import pandas as pd

df = df.sort_values(['segment', 'week']).copy()
df['previous_rate'] = df.groupby('segment')['key_outcome_rate'].shift(1)
df['wow_change_pp'] = df['key_outcome_rate'] - df['previous_rate']
df['rolling_mean'] = df.groupby('segment')['key_outcome_rate'].transform(lambda s: s.rolling(4, min_periods=2).mean())
df['rolling_std'] = df.groupby('segment')['key_outcome_rate'].transform(lambda s: s.rolling(4, min_periods=2).std())
df['z_score'] = (df['key_outcome_rate'] - df['rolling_mean']) / df['rolling_std']

anomalies = df[df['z_score'].abs() >= 2].sort_values('z_score')
print(anomalies[['week', 'segment', 'key_outcome_rate', 'wow_change_pp', 'z_score']])
```

This method signals variations worth investigating while avoiding knee-jerk reactions.

## Common mistakes to avoid

- Using overly aggregated data that hides opposing patterns
- Neglecting data quality checks (duplicates, incomplete tracking, timezone errors)
- Confusing correlation with causation

Every analysis should include at least three checks: explicit metric definition, segment comparison, and verification against baseline or control group.
