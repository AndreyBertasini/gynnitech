## Real problem

In data work with AI, the concrete challenge is to pick the right level of automation for each task without losing control over data, definitions, and decisions. Teams often want to speed up but risk relying on unverifiable outputs, which can affect budgets, compliance, and quality.

## Conceptual model

The work breaks down into four layers: task (what AI accelerates), context (data and constraints), control (how to verify output), and decision (which action to take). This model helps avoid two opposite mistakes: using AI only as text autocomplete or giving it decision-making autonomy without oversight.

| Layer | What to clarify | Example |
|---|---|---|
| Task | Which part of the work AI accelerates? | Query draft, checklist, memo |
| Context | What info makes the output useful? | Data schema, metric, time period |
| Control | How to detect if output is wrong? | Tests, baseline, review |
| Decision | What action follows if control passes? | Pipeline fix, deployment, recommendation |

## Rigorous formalization

To analyze the workflow, define the unit of work (operational rule, checklist, prompt, control, or go-no go decision), link observable signals (clarity, risk coverage, repeatability, ownership, utility), and state the expected decision: quickly choose the correct automation level for each data task.

| Element | Specification |
|---|---|
| Unit of analysis | Operational rule, checklist, prompt, control, or decision |
| Main signal | Clarity, risk coverage, repeatability, ownership, utility |
| Baseline | Manual process or current model |
| Decision | Correct automation level |
| Guardrail | Privacy, cost, data quality, interpretability |
| Main risk | Using cheat sheet as shortcut without review |

## Example or case study

Before delivering an AI-generated report, the analyst runs a checklist covering definitions, grain, segments, sources, baseline, recommendation, and stop condition. AI supports the decision cycle, but each step remains controllable.

| Evidence | Cautious reading | Action |
|---|---|---|
| Faster output | Speed is useful only if quality is maintained | Compare with baseline and independent review |
| Plausible explanations | Linguistic plausibility is not empirical proof | Translate explanations into data controls |
| Metric improvement | Possible composition effects or leakage | Segment, verify guardrails, monitor over time |

## Lab / exercise

### Basic level

Write a one-page sheet: decision to support, required inputs, expected output, minimum control, and main risk, using a simple case like a conversion change.

### Intermediate level

Build a table with three scenarios: manual workflow, AI-assisted, and heavily automated. Indicate time, quality, risk, control, and final owner for each.

### Research-grade level

Prepare a reviewable decision memo including hypotheses, required data, exclusion criteria, quality controls, decision threshold, residual risk, monitoring plan, and a "what would change the team's mind" section.

### Recommended datasets and materials

Use personal checklists, prompt examples, memo templates, quality gates, and post-mortem notes. If no real data is available, create a synthetic dataset with at least 200 rows, a time dimension, a segment dimension, a primary metric, and a field representing a potential quality error.

## Common mistake to avoid

Don't treat the cheat sheet as a label instead of a process: outputs without explaining data, controls, and decisions are insufficient. Don't confuse individual productivity with organizational reliability. Decide upfront which actions are allowed, which require approval, and which are forbidden.

Write three lines before starting:

| Line | Content |
|---|---|
| Decision | Which concrete choice to improve |
| Evidence | Which data or control supports the choice |
| Stop | Which risk would stop or require review |

If any is missing, the workflow isn't ready. AI can still support exploration but not replace decision-making.

## Quiz or checkpoint

1. Which concrete decision does this lesson improve?
2. Which part of the workflow can be delegated to AI and which must remain human-owned?
3. What baseline would you use to measure real improvement?
4. What failure mode could make an apparently correct output dangerous?
5. What artifact would you deliver to a stakeholder?

## Operational summary

The cheat sheet is useful when it produces a clear decision, not just terminology. Use the cycle decision, context, AI support, verification, and handoff to turn the lesson into verifiable practice. The more a workflow uses prompts, controls, metrics, and human review, the more it must be observable. Outputs that cannot be reconstructed or reviewed are not professional automation but just uncontrolled speed.
