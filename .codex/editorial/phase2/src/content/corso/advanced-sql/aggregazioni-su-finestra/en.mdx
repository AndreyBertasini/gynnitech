# Cohort analysis in SQL

## Real-world problem

High new sign-ups last month might look promising, but without knowing if those users are returning, the spike could just be noise from a marketing campaign. Looking at total active users alone hides this issue. Cohort analysis helps separate user groups by their entry time to observe retention and behavior over time.

## Conceptual model

Cohort analysis builds a matrix relating:

- Cohorts: groups defined by when users first took an action (e.g., signup month);
- Observation periods (month 0, month 1, etc.);
- Metrics of interest (e.g., percent of users still active).

This lets you answer questions like: Are we improving retention over time? Do newer users stick around longer than those from six months ago? Did the latest product change affect long-term behavior?

| Phase    | What to clarify                               | Output                  |
|----------|-----------------------------------------------|-------------------------|
| Question | Which real decision needs improvement?       | Decision to make        |
| Measure  | Which observable signal represents the issue?| Metric or raw data      |
| Control  | What baseline makes the result interpretable?| Credible comparison     |
| Action   | What changes after analysis?                   | Next operational step   |

## Rigorous formalization

To make cohort analysis reproducible and robust, define clearly:

- Unit of analysis (row, partition, window, join, cohort, or time metric);
- Main signal (accuracy, performance, duplicates, grain, and result stability);
- Baseline (prior period, comparable group, benchmark, or counterfactual);
- Expected decision (query, intermediate model, SQL test, or reusable pattern);
- Risks, such as mistaking an available number for sufficient evidence.

| Element        | Required specification                                   |
|----------------|----------------------------------------------------------|
| Unit of analysis| row, partition, window, join, cohort, or time metric    |
| Signal         | accuracy, performance, duplicates, grain, stability      |
| Baseline       | prior period, comparable group, benchmark, counterfactual|
| Decision       | query, intermediate model, SQL test, reusable pattern    |
| Risk           | Mistaking available number for sufficient proof          |

## Building the cohort matrix in SQL

Given a `user_activity` table with `user_id`, `signup_date`, and `activity_date`, the goal is monthly retention:

1. Assign each user to a cohort defined by signup month.
2. Calculate the period number for each activity month relative to signup.
3. Compute the percent of active users per cohort and period.

Key steps:

- Define cohorts and monthly activity:

```sql
WITH user_cohorts AS (
  SELECT user_id, DATE_TRUNC('month', signup_date) AS cohort_month
  FROM users
),
activity_by_month AS (
  SELECT DISTINCT uc.cohort_month, uc.user_id, DATE_TRUNC('month', a.activity_date) AS activity_month
  FROM user_cohorts uc
  JOIN user_activity a ON uc.user_id = a.user_id
)
```

- Calculate period number (0 = signup month):

```sql
cohort_activity AS (
  SELECT cohort_month, user_id, activity_month,
    (EXTRACT(YEAR FROM activity_month) * 12 + EXTRACT(MONTH FROM activity_month))
    - (EXTRACT(YEAR FROM cohort_month) * 12 + EXTRACT(MONTH FROM cohort_month)) AS period_number
  FROM activity_by_month
)
```

- Calculate retention and pivot matrix:

```sql
cohort_size AS (
  SELECT cohort_month, COUNT(DISTINCT user_id) AS num_users
  FROM user_cohorts
  GROUP BY cohort_month
),
cohort_retention AS (
  SELECT ca.cohort_month, ca.period_number, COUNT(DISTINCT ca.user_id) AS active_users,
    cs.num_users AS cohort_size,
    ROUND(COUNT(DISTINCT ca.user_id) * 100.0 / cs.num_users, 1) AS retention_pct
  FROM cohort_activity ca
  JOIN cohort_size cs ON ca.cohort_month = cs.cohort_month
  GROUP BY ca.cohort_month, ca.period_number, cs.num_users
)
SELECT cohort_month,
  MAX(CASE WHEN period_number = 0 THEN retention_pct END) AS month_0,
  MAX(CASE WHEN period_number = 1 THEN retention_pct END) AS month_1,
  MAX(CASE WHEN period_number = 2 THEN retention_pct END) AS month_2,
  MAX(CASE WHEN period_number = 3 THEN retention_pct END) AS month_3
FROM cohort_retention
GROUP BY cohort_month
ORDER BY cohort_month;
```

## Example case study

Peloton saw a surge in subscriptions during the pandemic, but cohort analysis revealed that pandemic-era cohorts had significantly lower 12-month retention compared to pre-pandemic cohorts. This insight led to marketing shifts targeting users more likely to stay engaged, improving business sustainability.

## Common mistakes to avoid

- Confusing cohort with period, mixing users of different ages and losing trend insights.
- Using incorrect denominators for retention, such as active users in the prior period instead of total cohort size.
- Failing to handle users who sign up late in the period, causing artificially low retention.
- Ignoring seasonality, comparing cohorts with naturally different patterns without adjustment.
