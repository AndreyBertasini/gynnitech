# Funnel analysis in SQL

In complex data environments, funnel analysis turns scattered events into clear, measurable steps. It is not just about counting how many users reach the last step but precisely defining entry points, order, and timing constraints to avoid misleading conclusions.

## Real-world problem

Product teams see many signups but few activations, marketing tracks different campaigns, and customer success notes tickets right after onboarding. A query is needed to connect these signals and reveal where users truly drop off.

## Conceptual model

A funnel is an ordered sequence of steps a user must complete. Key questions:

- How many users reach each step?
- How many move from one step to the next?
- Where is the largest absolute user loss?

Importantly, the bottleneck is not always the step with the lowest conversion rate but the one causing the greatest absolute loss.

## Rigorous formalization

To analyze a funnel in SQL, define:

- Unit of analysis: row, partition, window, join, or cohort.
- Main signal: correctness, performance, duplicates, grain, and result stability.
- Baseline: previous period, comparable group, or counterfactual scenario.
- Expected decision: query, intermediate model, test, or reusable pattern.
- Risk: mistaking an available number for sufficient evidence.

## Example or case study

HubSpot used funnel analysis to discover that a scoring algorithm update reduced the lead-to-MQL conversion rate but improved MQL quality. The decision was to adjust marketing quotas rather than revert the algorithm.

## Building the funnel in SQL

Start by aggregating events per user and extracting the timestamp of the first occurrence of each step. A simple query counts users reaching each step but doesn't ensure correct event order.

To enforce temporal order, use a CTE with conditions ensuring each step happens after the previous one. This prevents inflated counts from out-of-sequence events.

## FIRST_VALUE, LAST_VALUE, and NTILE: enriching the funnel

Window functions FIRST_VALUE and LAST_VALUE identify the first and last relevant event per user, useful for attribution and channel analysis. Be careful to specify the frame for LAST_VALUE; otherwise, it returns the current row's value instead of the last.

NTILE segments users into equal-sized buckets, useful to rank funnel completion speed.

## Lab / exercise

### Basic level

Build a basic funnel counting users per step in the purchase process (page_view, purchase).

### Intermediate level

Use FIRST_VALUE to identify each user's first acquisition channel and calculate conversion rates by channel.

### Research-grade level

Prepare a decision memo with hypotheses, data requirements, exclusion criteria, quality checks, decision thresholds, risks, and monitoring plans.

### Recommended datasets and materials

Use real or synthetic data with at least 200 rows, temporal dimension, segments, and outcome metrics.

## Common mistake to avoid

Don't treat funnel analysis as a mere label or chart without linking results to a concrete decision. If you can't say which choice you'd change based on the data, the analysis is incomplete.

## Operational summary

Funnel analysis becomes powerful only when it yields clear decisions and concrete actions. The discipline lies in rigorously defining units of analysis, metrics, baselines, and risks, and linking every result to an actionable choice.
