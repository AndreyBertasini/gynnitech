# Data visualization: principles and visual perception

A chart can be technically correct yet still mislead the viewer: compressed scales, colors without hierarchy, hidden comparisons, or legends far from the data can distort the message. Visualization is not decoration for metrics; it is a core part of analytical reasoning. This lesson teaches how to design what should be seen first, guiding attention effectively.

## Real problem

In the realm of dashboards and visualization, the challenge is to turn complex data into readable, actionable decision interfaces. This is not just theory or applying templates; it is about improving a concrete choice using data, explicit assumptions, and minimal controls. If at the end of your analysis you cannot say which decision changes, which data you observe, and which error you want to avoid, you have not yet gained applied competence.

## Conceptual model

The process breaks down into four fundamental phases:

| Phase    | What to clarify                                | Output                  |
|----------|-----------------------------------------------|-------------------------|
| Question | Which real choice should improve?             | Decision to be made     |
| Measure  | Which observable signal represents the problem? | Metric or source data   |
| Control  | Which baseline makes the result interpretable? | Credible comparison     |
| Action   | What changes after the analysis?               | Next operational step   |

Every technical deep dive should strengthen at least one of these points, always focusing on the decision to support.

## Rigorous formalization

To analyze data visualization rigorously, first define the unit of work (chart, metric, view, stakeholder, or recurring decision) and link it to an observable metric such as readability, usage frequency, decision time, or reduced ambiguity. Also declare the expected decision: dashboard, operational view, alert, or executive narrative.

| Element          | Required specification                                         |
|------------------|----------------------------------------------------------------|
| Unit of analysis | chart, metric, view, stakeholder, or recurring decision         |
| Main signal      | readability, usage frequency, decision time, reduced ambiguity  |
| Baseline         | Previous period, comparable group, benchmark, or counterfactual scenario |
| Decision         | dashboard, operational view, alert, or executive narrative      |
| Risk             | Mistaking an available number for sufficient proof              |

A solid formalization allows another analyst to reproduce the logic, critique assumptions, and reach the same decision from the same data.

## Example or case study

Imagine a team needing to show cohort retention to a non-technical audience. A single average line hides important differences, while a heatmap reveals them but requires a clear legend. The graphic choice changes the quality of the conversation and thus the decision.

| Observed evidence           | Careful interpretation                          | Recommended action           |
|----------------------------|------------------------------------------------|------------------------------|
| The number improves         | Could be a real effect or normal variation      | Seek comparison and segmentation |
| One segment changes more than others | The aggregate average hides a difference      | Separate cohorts or use cases   |
| Cost grows alongside result | Impact should be read on margin                  | Estimate trade-offs and sustainability |

## Common mistake to avoid

The most frequent error is treating **Data visualization: principles and visual perception** as a label rather than a process. This happens when a chart is shown without a decision, a metric without a baseline, or a conclusion without indicating which assumption might invalidate it. The control question is: if this result were unstable, which choice would I get wrong? Without a concrete answer, the link between analysis and action is missing.

## Visual perception and accuracy

Cleveland and McGill (1984) measured how accurately humans perceive different visual encodings:

| Visual encoding             | Accuracy    | Recommended use              |
|----------------------------|-------------|-----------------------------|
| Position on common scale    | Highest     | Bar chart, dot plot          |
| Position on aligned scales  | High        | Line chart                  |
| Length                     | High        | Bar chart                  |
| Angle/Slope                | Medium      | Pie chart (avoid!)          |
| Area                       | Low         | Bubble chart (use cautiously) |
| Color (saturation)         | Low         | Heatmap, highlights         |

Practical rule: use position (bars, lines) for precise values, color to draw attention.

## Choosing the right chart

| Question                   | Chart                | Why                                            |
|----------------------------|----------------------|------------------------------------------------|
| Compare categories          | Horizontal bar chart | Horizontal bars ease label reading             |
| Trend over time             | Line chart           | Eye follows line and perceives slope           |
| Distribution of a variable  | Histogram / Box plot | Shows shape, outliers, quartiles                |
| Relationship between two variables | Scatter plot        | Correlation, clusters, outliers                 |
| Part of a whole (few parts) | Stacked bar          | Avoid pie charts - eyes do not measure angles well |
| Geographic data             | Choropleth map       | If data has spatial dimension                    |

## Most common dashboard mistakes

1. Pie charts with more than 3 slices: human eye struggles to distinguish similar angles; use bar charts instead.
2. Dual Y-axes: allow scale manipulation to falsely imply correlation; avoid.
3. Rainbow colors for quantitative data: color lacks intrinsic order; use sequential scales (light to dark).
4. 3D without a third data dimension: distorts perception; never use 3D decoratively.

## Real case: Netflix and metric discipline

Netflix builds product decisions around observable behavioral signals: episode completion, search time before playback, early abandonment, return within a week, recommendation effectiveness. It does not measure just immediate clicks but also quality signals to avoid vanity metrics that look good short-term but harm long-term value.

This methodological approach shows how data visualization must connect to a concrete outcome: if the result does not help choose between two alternative actions, the analysis is incomplete.

## Summary

Data visualization becomes a decision-making tool when it connects problem, data, metric, segmentation, and action. It is not enough to say "the number went up" or "went down"; you must specify which decision to make, with what confidence level, and which metric will verify if you were right. Only then does visualization help make decisions under uncertainty.
