# Piano di Implementazione: Sistema di Sincronizzazione Bidirezionale Notion ↔ Astro

Questo piano descrive l'architettura e i passaggi per implementare un sistema di gestione contenuti completo che sincronizza Notion con Astro, permettendo di gestire blog, corsi e pagine direttamente da Notion.

## 1. Architettura del Sistema

Il sistema funzionerà principalmente con **Notion come "Single Source of Truth"** (Sorgente della Verità) per i contenuti, ma supporterà il flusso inverso per aggiornamenti di metadati e correzioni rapide.

### Flussi di Sincronizzazione
*   **Downstream (Notion → Astro):**
    *   Uno script Node.js/TypeScript interrogherà le API di Notion.
    *   Filtrerà i contenuti con stato "Published".
    *   Convertirà i blocchi Notion in Markdown/MDX (incluso frontmatter).
    *   Genererà/Aggiornerà i file in `src/content/`.
    *   Aggiornerà la configurazione del menu (`sidebar`).
*   **Upstream (Astro → Notion):**
    *   Scansione dei file locali per modifiche (hash/timestamp).
    *   Aggiornamento delle proprietà su Notion (es. "Last Sync", correzioni Titolo/Descrizione).
    *   *Nota:* La modifica del corpo del testo da Astro a Notion sarà implementata come "best-effort" per evitare la corruzione di blocchi complessi.

## 2. Schema Database Notion

Per supportare i requisiti, configureremo un Database Notion unificato con le seguenti proprietà:

| Proprietà Notion | Tipo | Mapping Astro | Note |
| :--- | :--- | :--- | :--- |
| **Name** | Title | `title` | Titolo del contenuto |
| **Slug** | Text | nome file | URL amichevole (es. `my-post`) |
| **Type** | Select | `collection` | Valori: `Blog`, `Course`, `Page` |
| **Status** | Status | - | `Draft`, `Published`, `Scheduled` |
| **Publication Date** | Date | `date` | Data di pubblicazione/scheduling |
| **Summary** | Text | `description` | Meta description SEO |
| **Category** | Select | `category` | Per il blog |
| **Tags** | Multi-select | `tags` | Tag vari |
| **Author** | Person | `author` | Autore del post |
| **Cover Image** | Files | `image` | Immagine di copertina |
| **Menu Visibility** | Checkbox | - | Se mostrare nel menu di navigazione |
| **Parent/Module** | Relation | - | Per gerarchia corsi (es. Modulo 1) |
| **Order** | Number | `order` | Ordinamento manuale |

## 3. Stack Tecnologico & Dipendenze

Aggiungeremo le seguenti librerie al progetto:
*   `@notionhq/client`: Client ufficiale API Notion.
*   `notion-to-md`: Per convertire i blocchi Notion in Markdown.
*   `gray-matter`: Per gestire il frontmatter dei file MDX.
*   `dotenv`: Per gestire le chiavi API in locale.
*   `tsx`: Per eseguire gli script di sync TypeScript.

## 4. Fasi di Implementazione

### Fase 1: Setup e Configurazione
1.  Installazione dipendenze.
2.  Creazione struttura directory per gli script di sync (`src/lib/notion/`, `scripts/`).
3.  Definizione delle interfacce TypeScript per i tipi di contenuto.

### Fase 2: Sviluppo Script di Sync (Notion → Astro)
1.  **Notion Client:** Setup autenticazione e query database.
2.  **Content Parser:** Implementazione logica di trasformazione (Blocks → Markdown).
3.  **File Manager:** Funzioni per scrivere file `.mdx` nelle cartelle corrette (`src/content/blog`, `src/content/corso`, ecc.) basandosi sulla proprietà `Type`.
4.  **Menu Generator:** Generazione automatica di un file JSON per la sidebar di Starlight basata sulla proprietà `Menu Visibility` e `Order`.

### Fase 3: Gestione Menu e Configurazione Astro
1.  Modifica di `astro.config.mjs` per caricare dinamicamente la sidebar da un file generato (es. `src/data/sidebar-generated.json`).
2.  Adattamento delle Content Collections esistenti se necessario.

### Fase 4: GitHub Actions (CI/CD)
1.  Creazione workflow `.github/workflows/sync.yml`.
2.  Configurazione trigger:
    *   **Schedule:** Esecuzione ogni ora (o frequenza personalizzata).
    *   **Workflow Dispatch:** Pulsante manuale per forzare il sync.
3.  Commit automatico: Il workflow committerà le modifiche al repo se ci sono nuovi contenuti.

## 5. Deliverables

Al termine avrai:
1.  `scripts/sync.ts`: Il motore di sincronizzazione principale.
2.  `src/lib/notion.ts`: Libreria di supporto per l'integrazione.
3.  Configurazione GitHub Actions per l'automazione.
4.  Documentazione su come duplicare e configurare il template Notion.
